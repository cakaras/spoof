Popup Address Bar Spoofing — Research PoC

window.open() attack surface · about:blank · blob: · navigation timing

T1 · about:blank → document.write() → navigate HIGH IMPACT
Buka about:blank popup, inject konten via document.write(), lalu panggil history.pushState() dari dalam popup untuk ubah URL bar ke target domain. about:blank mewarisi origin opener sehingga pushState bisa mengubah URL ke path apapun dalam origin yang sama.

Variant tambahan: Setelah write, popup navigate ke blob: URL yang mewarisi origin — address bar menunjukkan blob:https://attacker.com/uuid yang terlihat seperti origin legit.
T2 · Popup + Fullscreen dari dalam popup context MEDIUM
Buka popup via window.open(), inject payload, lalu panggil requestFullscreen() dari dalam popup bukan parent. Fullscreen dari popup context → Chrome Android kadang tidak attach hint ke popup window, atau hint muncul di parent bukan popup.

Tambahan: Popup fullscreen sambil parent window melakukan history flood untuk saturasi navigation manager.
T3 · blob: URL popup — address bar shows partial origin HIGH IMPACT
Buat Blob berisi payload HTML, generate URL.createObjectURL(), buka via window.open().

Address bar popup akan menampilkan: blob:https://[opener-origin]/[uuid]

Key insight: Jika attacker host di domain yang mirip target (misalnya accounts-google.com), address bar akan tampil blob:https://accounts-google.com/... — sangat convincing. Tidak ada fullscreen, tidak ada hint, tidak ada indikator suspicious.
T4 · window.open() + location.replace() timing race TIMING RACE
Buka popup ke URL target legit, lalu race antara location.replace() dan rendering. Pada beberapa versi Chrome Android, ada race window dimana address bar masih menampilkan URL lama saat konten sudah diganti.

Classic technique — dicoba dengan timing yang lebih surgical menggunakan requestAnimationFrame chain.
